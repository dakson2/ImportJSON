## 1. What is physically impossible from this session

Two hard limits, both verified by test rather than assumed.

**No outbound web.** Every job source, LinkedIn, and every employer domain is refused by the network policy at the
CONNECT stage — `weworkremotely.com`, `dynamitejobs.com`, `jobs.lever.co`, `job-boards.greenhouse.io`,
`jobs.ashbyhq.com`, `linkedin.com`, even `onthegosystems.com`. So: no live crawl, no employer-direct verification,
no LinkedIn visit, no ATS submission, no contact-form submission.

The exception is interesting: **`googleapis.com` is open.** `sheets.googleapis.com` answers, and an unauthenticated
call returns Google's own error — *"Method doesn't allow unregistered callers… Please use API Key or other form of
API consumer identity."* A POST to `oauth2.googleapis.com/token` also answers properly, so service-account token
minting would complete from here.

**No way to write spreadsheet cells.** The Google Drive connector is file-level, not cell-level: it reads, creates,
copies, shares and trashes files, and its `update_file` changes only title and parent folder. There is no Google
Sheets connector in the claude.ai directory at all — only third-party spreadsheet products. The env var
`CLOUDSDK_AUTH_ACCESS_TOKEN` is a 14-character placeholder that Google rejects as `invalid_token`.

So the missing piece is precisely **one Google credential**, not network access and not a settings mistake.

### The fix, in order of preference

1. **Service account.** Create one, enable the Sheets API, share `Work` and `Base` with its email as Editor, and put
   the JSON key into the environment as a **secret** — never into chat, Sheets, Docs or Git, per the project's own
   rule on credentials. Cells then get written directly, and the Apps Script bridge below becomes unnecessary.
2. **Apps Script bridge.** `ADX_Bridge.gs` in this folder, pasted into the `Work` spreadsheet once. Note that
   `script.google.com` is the one blocked Google host, which is why the bridge is built around a Drive inbox and
   receipt files rather than an HTTP endpoint.
